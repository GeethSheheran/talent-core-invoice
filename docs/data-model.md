# Data model and privileges

The migrations are the authoritative schema. UUIDs identify records; company codes and issued numbers are display identifiers. Money is integer minor units, capped at 1,000,000,000,000 per invoice/payment; v1 supports two-decimal LKR, USD, EUR, GBP, AUD and INR. Quantities use numeric(12,3). PostgreSQL rounds row amounts and post-discount percentage tax to the nearest minor unit; Decimal.js matches that behavior in previews.

`admin_members` is the sole authorization source. All public tables enable RLS. Authenticated users receive SELECT only; policies require protected active membership. Membership itself allows self-read only. Anonymous users receive no table access. Financial RPCs are SECURITY DEFINER because table writes are deliberately revoked; each public admin mutation checks `private.assert_admin()`, uses an empty search_path, and qualifies object names. PUBLIC/anon execution is revoked. `scan_daily` and `claim_jobs` are service-role only. `private.is_admin` is the small definer membership lookup; `private.balance` runs with invoker permissions. The dashboard balance view uses security_invoker.

Company locks serialize all financial mutations for that company. Counters also lock through atomic upsert. Unique constraints cover numbers, agreement/period, payment/invoice allocation, one reversal/payment, one document/record/version, outbox keys and reminder invoice/rule/date/channel. This app has no generic financial-table update endpoint.

Core: companies, projects, catalogue, agreements and effective agreement_services. Billing: invoices, invoice_items, invoice_balance_references, document_counters. Cash: payments, payment_allocations, payment_reversals. Corrections: credit_notes identify commercial corrections; credit_note_allocations identify the original charge being corrected; credit_applications alone reduce receivables. The v1 correction RPC creates and applies the whole credit to its originating invoice atomically. It does not create a second pool of spendable cash. Confirmed-payment excess is reusable through additional payment_allocations with an idempotency key.

Proposals store editable current content and proposal_versions on every save. Issue freezes a snapshot; acceptance is separate. document_files stores immutable private paths, checksums, branding/template version and retry state. Delivery attempts separate queue, acceptance, delivered, failed, mock and external states. Notifications, outbox jobs, job runs and audit logs preserve operational history.

The privileged client is server-only and used for bootstrap, private file archival, delivery/webhook updates and cron. It is never used as a substitute for checking the interactive administrator. Storage allows admin reads of the private documents bucket; only the server adapter writes files.

Company expenses are stored in `company_expenses`, with an optional `invoice_id` reservation and an `invoice_items.expense_id` source reference. Existing invoice history remains intact when a void releases the reservation. Agreements support `repeat` (monthly/annually), nullable billing-day and reminder-day overrides, and recurring tax/discount/notes. Upcoming billing events have a null `rule_id`, the `billing` channel, and one event per invoice; unpaid-invoice follow-ups retain their existing rule-based identity.
