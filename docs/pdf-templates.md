# Documents

`templates/documents/document.tsx` renders Invoice, Proposal, Receipt and Current Statement through one shared identity. There is exactly one invoice template. Browser previews and PDF rendering validate snapshots with the same Zod contract. Issued snapshots embed configured font/logo data, brand tokens, sender/client details, rows and references. Dynamic prose is React-escaped and is never interpreted as HTML.

`PdfRenderer` is replaceable; the provided `ChromiumRenderer` uses puppeteer-core and @sparticuz/chromium in the Node runtime. On macOS/Windows use an explicit installed Chrome path. The renderer accepts structured snapshots only, disables document JavaScript, blocks all non-data network requests, waits for fonts/images and closes the browser in a finally block. It does not navigate to supplied URLs. Configurable asset paths are restricted to local `/brand/` PNG/JPEG and WOFF2/TTF files, capped at 2 MB each. Missing optional assets fall back to text/system typography.

Issue/confirmation creates pending document metadata before rendering. Render failures set a visible retry state; they do not roll back the issue or allocate a new number. PDF bytes are archived to private Storage under record/version/checksum paths. Ready files are never replaced. Downloads use a 60-second signed URL after independent admin authorization. The runtime filesystem is not the persistence layer. Current statements stream from a read-only balance query and do not modify transactions.

`npm run pdf:smoke` renders a 70-row invoice and a 10-section proposal in local Chrome. `.artifacts/` is ignored. A4 pagination uses natural content flow, repeated table headings and selectable text. Long tables are not marked unbreakable. Header/body/footer and page numbers were inspected on rendered PDF pages. Production Linux font substitution and hosting execution limits still need a deployed smoke test.

An external renderer adapter, if needed later, must receive validated snapshots/trusted server-rendered content, authenticate requests, forbid arbitrary URLs, enforce time and size limits, and preserve the same archival contract. No external service is configured or claimed operational here.

The server pair is pinned to Chromium 153 and Puppeteer 25.11, following the [official supported-browser mapping](https://pptr.dev/supported-browsers). Chromium requires Node ^22.17 or >=24; use a current supported Vercel Node runtime.

## Browser selection and retries

PDF rendering honors `CHROME_EXECUTABLE_PATH` when set and validates that the executable exists. Without that override, macOS detects installed Chrome or Chromium, Windows checks standard Chrome/Edge locations, and Linux uses the packaged serverless Chromium binary. Restart the app after changing the executable override. The PDF smoke test exercises the same selection logic as the app.

Failures record whether rendering, private Storage upload, or archive metadata saving failed. The server logs the document ID and failure stage for diagnosis; the UI preserves the original issued snapshot and offers a retry. Successful generation refreshes the page and unlocks the invoice sending step. The number and accounting state are never regenerated by a PDF retry.
