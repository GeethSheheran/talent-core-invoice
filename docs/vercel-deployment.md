# Vercel deployment

No deployment was performed. Use a commercial-appropriate Vercel plan for this business application; confirm current plan terms, function resources and cron behavior before enabling production work.

1. Push the reviewed repository and lockfile to your Git provider. Import into Vercel with Next.js detection, root at this repository, install `npm ci`, build `npm run build` and Node 22.x (or a tested compatible newer Node release). The build uses supported webpack after Turbopack worker socket failures in the development sandbox.
2. Configure a dedicated production Supabase project, apply reviewed migrations and bootstrap the intended administrator. Follow supabase-setup.md. Use the final HTTPS application domain for APP_URL, Auth site URL and callback allowlists.
3. Configure production secrets in the Vercel dashboard. Preview deployments must use a different development project, EMAIL_PROVIDER=mock (or DEV_EMAIL_RECIPIENT), and ENABLE_PRODUCTION_JOBS=false. Do not copy production keys to previews. VERCEL_ENV is provider-controlled; never force it to production locally.
4. Confirm the private documents bucket, issuer business settings, numbering format, logo/font paths, sender domain and webhook signature secret. Test a fictional invoice, receipt, multipage proposal and statement in an isolated deployment.
5. `vercel.json` schedules `/api/cron/daily` at `30 3 * * *`: 03:30 UTC / 09:00 Asia/Colombo. Set a strong CRON_SECRET; the route verifies the Bearer value with a timing-safe comparison. Enable production jobs only after setup by setting ENABLE_PRODUCTION_JOBS=true. Use this scheduler only, not a duplicate Supabase cron. Execution time is not guaranteed; scans catch up and use unique keys.
6. The Node PDF routes request 60 seconds. Chromium is traced into route bundles, with local brand assets and print CSS. Verify bundle size, memory, cold-start time and timeout on the selected plan. Vercel currently documents a 250 MB uncompressed function bundle limit; confirm the applicable limits at deployment time. Local rendering is not proof of deployment compatibility. If the chosen plan cannot reliably render, supply a reviewed external PdfRenderer adapter before launch.
7. Monitor failed document renders, delivery attempts, outbox terminal failures and job_runs. Verify cron authorization and scheduler invocation in the live environment only after live configuration is explicitly authorized. Test that missing/invalid webhook signatures are rejected.

Official references checked during implementation: [Next.js installation](https://nextjs.org/docs/app/getting-started/installation), [Vercel function limits](https://vercel.com/docs/functions/limitations), [Vercel cron management](https://vercel.com/docs/cron-jobs/manage-cron-jobs), and [serverless Chromium](https://github.com/Sparticuz/chromium). Review them again when deploying; plan resources and pricing can change.

Release gate: hosted authorization/Storage acceptance, real multi-connection transaction tests, production PDF resource verification, verified sender/webhook, restore drill and no unreviewed production credentials in preview. Do not send client invoices as part of a smoke test.
